## 持ち主へ問う項

### 問 1. 要件書 第 1.27 版と第 1.28 版の発効（Q93-4・Q94-1・Q95-2・Q96-1・Q97-2・Q99-3）

**やりたいこと。** 要件書を 2 版まとめて発効させたい。第 1.27 版は便 90 が起草したまま承認待ちで、要件の項に判断の記録だけを受ける欄を足して 13 対を写した版である。第 1.28 版はこの一括で起草したもので、中身は 5 つある。

1. **FR14（機械が読む id の索引）の改訂。** いまの字は口の名を持たず、起動の条件を「folio build が実行されたとき」、索引の中身を「文書・要件・契約の id と 1 行の題」と書く。着地した口は `folio graph --print` で、起動の条件も中身も違う。要件の趣旨（機械が読む id の索引を出す）は同じなので、番号を動かさずに字を実装へ合わせる。
2. **新しい要件 FR21（全体像の短い出力）。** `folio graph --digest` と、席が始まるときの 1 行に当たる要件が要件書に無い。FR3（未整備のあいだの 1 行・1 回きり）はこれを覆わない。
3. **FR17（材料の束）の改訂。** 規範文が束の中身を「正本の写し（基準）」と書くが、次の便は観点が読むと宣言した節まで絞った写しにする。その 1 句を足す。
4. **FR19（生成区間への導出）と受入基準 AC17 の改訂。** 対象の file を字で並べる要件で、注が「増えるたびにこの要件の文に足す」と書く。便 95 で索引の欄の決まりの正本が 9 本目の対象になったので足す。
5. **FR20（天井の印と門）の改訂。** 規範文が印の中身を数え上げているが、便 99 が足した節点ごとの要約値の表と残差の要約値がその字の外にある。

### 問 2. 規則の表の行 R-17 の改訂（Q93-1・Q93-2・Q93-3）

**やりたいこと。** 「文章の中で id を指したなら、型付きの欄にも書くこと」という行の字を 3 か所直したい。

### 問 3. 判断の記録 ADR-14 の発効と、ADR-13 の注の訂正（Q94-2・Q94-3・Q94-4・Q95-1・Q97-5・Q99-1）

**やりたいこと。** 発効した判断の記録 ADR-13 のうち、決定 (1) だけを 2 か所で狭める新しい判断の記録 ADR-14 を発効させたい。残りは ADR-13 の注に訂正として書く。

- **ADR-14 の決定 (1)。** 索引の節点を「設計文書の中で id を持つ行」に閉じる。ADR-13 は「id を持つ行と、所見の置き場になる節」の 2 つを節点にすると書いていたが、節のほうは正本に id が無く、索引が自分で id を作るしかない。そうすると id で参照するという条（P-5.2）の指す先が、索引の中にしか無い id になる。
- **ADR-14 の決定 (2)。** 索引の欄の決まりの正本を、天井の読む文書の一覧にだけ載せる。入口の棚には載せない。棚の説明（あなたが承認した第 0.3 版の逐語）が「道具自身の正本は載せない」と定めているためである。
- **ADR-13 の注の訂正 4 点。** ① 決定 (2) の「11 型」は名前空間を畳んだ数えで、実装の閉じた一覧は 17 型である ② 決定 (5) の「精度は同じか上がる」は読む欄の宣言を広げることが前提である（問 4） ③ 決定 (16) の ⑤ は 2 便に割った ④ 帰結の「新しい要件 3 本」の 1 本目は既に在る FR14 の改訂に当たる。**決定と帰結の本文は 1 字も変えない。**

**理由。** 節を節点にすると増える辺は 48 本だが、その出所（観点が読む文書・入口の棚の関係と付録・設計ノートの節の参照）は 4 つとも別の正本が型付きで既に持っており、索引に入れなくても引ける。一方で「正本に無い id を導出物が作る」形は、id で参照するという決まりの土台を崩す。棚のほうは、載せると承認済みの 1 文を書き換えることになる。注の 4 点は数と名の訂正で、数の正本は実装の型付きの定数とその写しを持つ生成区間なので、判断の記録に数を写し直すと同じ数が 3 か所に在ることになる（条 P-6.3）。

**代替案。** ① 節も節点にする便を起こす（案 b・ADR-14 の退けた案に理由つきで並べた）。② 棚にも載せる（案 c）。③ 決定 (2) の「11 型」を 17 に書き換える。④ ADR-13 そのものを版上げする。判断の記録は承認欄を 1 つしか持てない形なので、版を上げると発効の承認の記録を上書きすることになる。改訂は新しい判断が `revises` の欄で指す形が、欄の決まりの定める向きである。

**あわせて 1 つ足す提案。** 索引が読まない欄のうち `outputs.from`（要件書の出力の行が要件を指す欄・3 本）は、両端とも節点なので辺にできる。辺を足すだけの変更は周の引き金に数えない（決定 (8)）ので安い。小さな便 1 本で足すことを勧める。

**コスト。** 判断の記録 1 本の承認と、ADR-13 の注の 1 段落。`outputs.from` を足すなら小さな便 1 本。実装は ADR-14 の発効そのものでは動かない。

**推奨。** ADR-14 を発効し、ADR-13 の注の訂正 4 点を同じ承認で通す。`outputs.from` も足す。

### 問 4. 天井の正本 第 0.11 版と、便 1 本ぶんの承認（Q97-1・Q97-3・Q99-5）

**やりたいこと。** AI の審査（天井）の正本を 3 つの向きで動かしたい。

1. **観点が読むと宣言する欄を 8 対広げる（本一括で書いた第 0.11 版）。** 次の便は材料の束を、観点が読むと言った章まで絞る。いまの宣言のまま絞ると、直近 10 周の所見の根拠 183 件のうち 17 件が束の外へ出る。その 17 件は面には出ているので、観点は面を見て正しい所見を立て、床が「根拠が正本に無い」と言って落とす。8 対を足すと落ちは 0 件になる。
2. **索引の欄の決まりの正本を、読む文書の一覧に足す（便 1 本）。** いま天井が読む文書は 9 本で、便 95 が新しく置いた索引の欄の決まりはどちらの一覧にも入っていない。入っていないので、そこを書き換えても周の引き金が立たない穴が 1 つ残る。
3. **材料の束の骨格の 6 語を生成区間へ写す（便 1 本）。** 束の組み立て方を決める 6 語は実装の型付きの定数だが、人が読める写しがどこにも無い。憲法 P-5.6 は、実装の定数を規則の正本にしているあいだはその写しを設計文書の置き場へ決定的に導出することを求める。

**理由。** 1 は次の便（束を絞る便）の前提で、これが無いと便が着地した瞬間に床が正しい所見を落とし始める。2 と 3 はどちらも天井の正本の版上げを伴うので、1 便にまとめて運べる。

**代替案。** ① 広げずに絞る便を着地させる（落ちが 17 件出る）。② 索引の欄の決まりを入口の棚にも載せる（問 3 の案 c）。③ 骨格の写しを持たない（条 P-5.6 に反する）。④ 骨格の写しを新しい file に置く（file が 1 本増える）。

**コスト。** 1 は承認 1 回だけで、実装は 1 行も動かない。2 と 3 は便 1 本（実装の固定長の定数 2 本・生成区間・凍結 anchor が同時に動く）。**観点の数（4 つ）と重さの値域は動かない**（条 N-5）。

**推奨。** 3 つとも進める。1 は本一括の PR で、2 と 3 は次の便 1 本で運ぶ。

### 問 5. 束を行の中の欄まで降りて絞るか（Q97-6）

**やりたいこと。** 材料の束をどこまで細かく絞るかを決めたい。いま採ろうとしているのは「最上位の章まで」で、もう 1 段細かい「章の中の欄まで」も測ってある。

**理由。** 細かく絞るほど AI に渡す字数は減るが、落ちる根拠が増える。直近 10 周の実測では、章まで（宣言を広げた後）で落ちは 0 件、欄まで降りると 25 件（13.7%）である。字数は目的関数ではないので、落ちが 0 の案を採るのが筋である。

**代替案。** 宣言を 8 対広げた後にもう一度測り直し、欄まで降りても落ちが 0 なら降りる。測り直しは 1 回ぶんの手間で済む。

**コスト。** 降りないなら 0。降りるなら実測 1 回と、便 98 の設計の書き直し。

**推奨。** 降りない。撤退条件の数えで必要になったときに測り直す。
