### 🔴 問 3. 判断の記録 ADR-22 の発効との依存（整合 F-1〔止める〕・F-2・F-3）

### 🔴 問 4. 憲法の schema 節の live の規則と `folio check` の食い違い（実態 F-1〔止める〕）

**やりたいこと。** 憲法の schema 節は「kind が reject / build-check でも live が now でない条は、その検査結果を「まだ分からない」として出す（P-4.2）」と約束する。今その条は 6 本（P-11・P-13・P-15・P-17・P-18・A-3・どれも live M1）で、`folio check` はそれを出さず「合格（違反 0・まだ分からない 0）」を返す（反証 支持）。これを実装の便で閉じる。便の形を次の 3 案から選ぶ。

- **(a) 約束どおり 6 条を「まだ分からない」に数え、`folio check` の判定を「まだ分からない」（rc 2）にする。** 一番正直である。ただし床は 6 条の機構が動くまで合格せず、器の受付と便の検証の前提「床 4 本が rc 0」と、check の合格を前提にする歯と、凍結 anchor（floor_cases の rc 0 を期待する 21 case）が動く。運び方が大きく変わる。
- **(b) 6 条を条ごとに「機構未稼働（まだ分からない）」として出し、要約の行に別枠で数える**（例「合格（違反 0・まだ分からない 0・機構未稼働 6）」）。判定の値と rc は今のまま。schema 節の「出す」は満たし、判定には数えない。
- **(c) schema 節の約束を「対象外」に改める**（条文の改訂・条 A-2）。実装は変えない。ただし条 P-4.1（実行できなかった結果を「異常なし」として扱わない）の向きに逆らう。

**推奨 = (b)。** 条 P-4.2 の「判定できないものは まだ分からない として表に出す」を条ごとの行で満たし、条 P-4.1 の「異常なしとして扱わない」は要約の行の別枠で守り、運び方は変えない。

**(b) が schema 節の改訂を要するかの断り。** 起草役の読みでは、要る見込みがある。schema 節は「その検査結果を「まだ分からない」として出す」と書き、要件書の 3 値（verdicts の「まだ分からない — 検査できなかった」・要件 FR5「実行できなかった検査を合格と表示しない」）と並べると、条ごとに「まだ分からない」を出しながら要約で「合格」と言う形が、同じ 3 値の中で割れると読める。**席の裁定で、独立の検証役にこれを確かめさせる。** 要ると判じられたら、schema 節の字に 1 句（機構未稼働の条は判定の値に数えず、条ごとの行と要約の別枠に出す）を足す改訂が条 A-2 の手順（判断の記録と撤退条件を先に書き・敵対の検証・承認・憲法の版）に掛かり、行 D-14 の止める場合 (イ) の例外として、この問の答えの後に判断の記録の承認要求を別に出す。そのとき、前文の平易文の言い換え（読みやすさ F-1）を同じ改訂に載せるかも同じ承認要求で問う。

**理由。** 文書が「出す」と約束し実装が 0 件を出すのは、実態と逆の約束である（止める）。day-1 の Python の床は約束を果たしていたが、Rust の床へ写したときに落ちた。

**コスト。** 便 1 本（M）。見積は §C の中身。案 (b) で schema 節の改訂が要らなければ、便は設計文書の置き場の file を書き換えないので、行 D-14 の窓の中でも器へ出せる。改訂が要るなら、判断の記録 1 本と憲法の版 1 つが加わる。
