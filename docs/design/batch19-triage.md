### 🔴 問 3. 判断の記録 ADR-3 決定 (8) を狭める判断の記録を起こすか（整合 F-1〔止める〕・F-2・F-5 の判断の記録の側）

**やりたいこと。** 判断の記録 ADR-3 決定 (8)（2026-09-16）は「契約表を今の形で着地させ、folio2 の M1 で設計ノートの YAML 正本と導出物へ移す」順序を今も決めている。後の判断の記録 ADR-16 は導出物の口を M3 に置き、ADR-21 は scribe2 の設計文書の移行の取りやめで論点を閉じたが、どちらの改訂の欄にも ADR-3 決定 (8) を狭める行が無い（反証 支持）。同じ形で、ADR-6 決定 (2) ③ の「判断の記録は最初 0 本の棚」も、ADR-16 決定 (2)(カ) の骨格が 1 本を書く決めと改訂の欄で結ばれていない。**新しい判断の記録を 1 本起こし、その改訂の欄（狭める向き）で ADR-3 決定 (8) と ADR-6 決定 (2) ③ を狭め、決定の本文は書き換えない**（ADR-20 が ADR-18・ADR-13 を狭めたのと同じ形）。狭め方の案＝ADR-3 決定 (8) は「folio2 自身の契約表を M1 で設計ノートの YAML 正本へ移す」に限り、導出物は ADR-16 決定 (5)(7) の M3、scribe2 の設計文書の移行は ADR-21 の取りやめに従う／ADR-6 決定 (2) ③ は骨格の命令を使わない置き場に限る。同じ承認で、制約 CON8 の頭の文を当時の順序として過去の字にし（整合 F-2）、要件書の次の版に載せる。

**理由。** 発効した 2 つの判断の記録が「M1 で移す」と「M3・取りやめ」を同時に持ち、注では狭められない（判断の記録の欄の決まりの改訂の欄の注が、範囲を変える口は改訂の欄だとする）。要件書の字だけを直すと、要件書が判断の記録の決定を狭めることになる。

**代替案。**
- **(A) ADR-21 の改訂の欄に行を 2 つ足す**（新しい判断の記録を起こさない）。記録の数は増えない。ただし発効した ADR-21 の改訂の欄（周の引き金の欄）を後から変えることになり、その変更の判断の記録と撤退条件が無い（条 A-2 の手順の外）。
- **(B) 注で断るだけにする**（ADR-3 と ADR-6 の注に「後の判断で範囲が変わった」と書く）。一番軽い。ただし反証の記録どおり注は決定を狭める口ではなく、次の周の整合が同じ 止める を立て直す見込みが高い。

**コスト。** 判断の記録 1 本（起草・敵対の検証〔条 A-2.3〕・独立の検証・承認要求）と承認 1 回。条文は変えない。周の引き金の欄が動く（判断の記録の状態と改訂の欄・制約 CON8）ので、承認の後に周を回す。実装と床の歯は動かない見込み。

**推奨 = 新しい判断の記録を起こす（代替案は採らない）。答えを得たら席が起草し、承認要求を別に出す。**

### 🔴 問 4. 憲法の schema 節の live の規則と実装の食い違い（実態 F-1〔止める〕）

**やりたいこと。** 憲法の schema 節は「kind が reject / build-check でも live が now でない条は、その検査結果を「まだ分からない」として出す（P-4.2）」と約束する。今その条は 6 本（P-11・P-13・P-15・P-17・P-18・A-3・どれも live M1）で、`folio check` はそれを出さず「合格（違反 0・まだ分からない 0）」を返す（反証 支持・day-1 の Python の床は出していたが Rust の床へ写したときに落ちた）。**schema 節の字を実態に合わせる改訂を起こす**＝新しい判断の記録と憲法の次の版（第 1.4 版）で、規則を「live が now でない条は `folio check` の判定に数えず、憲法の面の機構の欄に live の段の名札（「M1 で動く」）を出し、その条の充足は「まだ分からない」として扱い合格とは言わない（P-4.2・P-3.3）」の形に改める。

1. 上の向き（schema 節の改訂）を採るか。
2. 採るなら、同じ改訂に前文の平易文の「全部そろえる」と「そろっている」の言い換えの直し（読みやすさ F-1）を載せるか。推奨 = 載せる（前文も条 A-2 の改訂の範囲で、別に版を上げると改訂が 2 回になる）。

**理由。** 文書が「出す」と約束し実装が 0 件を出すのは、実態と逆の約束である（止める）。直し方は 2 つだけで、どちらも枝では閉じない。床に入れると、`folio check` は 6 件の「まだ分からない」で rc 2 を返し続け、床 4 本を rc 0 で受ける今の運び方（便の verify・受付の precheck・門）が 6 条が M1 で動くまで全部止まる。schema 節の字を改めれば、床は今のまま、黙る範囲は面の名札と条の注で見え、条 P-4.2 の「表に出す」は面が担う。

**代替案。**
- **(A) 床に入れる便を先に出す**（字は変えない）。約束の字は広いまま保てる。ただし上のとおり床が rc 2 を返し続け、運び方の変更（rc 2 を受ける手順か、live でない条の まだ分からない を判定から外す規則）が要り、後者は結局 schema 節の改訂になる。
- **(B) 6 条の機構の注で断る**（字も床も変えない）。一番軽い。ただし schema 節の約束は字のまま残り、次の周の実態が同じ 止める を立て直す見込みが高い（反証の記録は、注の「まだ分からないとして扱う」は人の扱いの宣言で検査結果の出力ではないと結んだ）。

**コスト。** 判断の記録 1 本と憲法の版 1 つ（条 A-2.1〜A-2.3＝判断の記録と撤退条件を先に書き、敵対の検証を添え、持ち主の承認〔逐語・日付・裁定 id〕を得てから版を上げる）。`folio inject` の生成区間は動かない見込み（schema 節は生成区間に写さない・前文の平易文も写さない）。凍結 anchor に憲法の新しい版の写しが増える（上書きしない）。面の名札の字を「まだ分からない」に寄せるかは、その判断の記録で決める（便が要るかも同じ）。

**推奨 = 1 は schema 節の改訂を起こす・2 は載せる。答えを得たら席が判断の記録を起草し、承認要求を別に出す。**
