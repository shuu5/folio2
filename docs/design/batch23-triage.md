### 判定 1 ＝ FR20 の規範文に「同じ根で照らせる」前提を上げる（注だけにしない）

- **所見の指摘は正しい。** 規範文は「その一覧に設計文書の置き場の file が 1 つも無ければ 0（通す）」と言い切る。便 142（台帳 f2-648.214・2026-09-25 着地）の後の実装 `crates/folio/src/gate.rs` の `run` は、その判定より前に、`--dir` が今の dir の下に在るか（`dir_parts`）と、write-set の各 path が同じ根からの相対で読めるか（`other_root`）を確かめ、照らせなければ 2 を返す。だから今の dir の外の `--dir` と実装の file だけの write-set には 2 を返し、規範文の字だけを読むと答えが逆に読める。前提は第 1.44 版の注と契約 `docs/design/delivery-142.md` §1 (a) の 5 にしか無かった。
- **規範文に上げる字は実装の字に合わせた。** 照らせない場合は実装の 2 つの定数と 3 つの判定に合わせて書いた。1 つ目は `UNKNOWN_DIR_OUTSIDE`（`--dir` が今の dir の下に無い）。2 つ目は `UNKNOWN_OTHER_ROOT` で、write-set の path が絶対 path・`..` の要素を持つ・`--dir` の途中の要素から始まる（`other_root` の 3 つの枝）。撃ち直し方は `FROM_THE_TOP`（作業ツリーの一番上から撃つ）である。「file の有無を判定せず」は、`run` がこの確かめを設計文書の判定（`is_design_source`）より前に置くことの字である。
- **「照らせるとき、」の句で既存の文をつないだ。** 既存の「その一覧に…が 1 つも無ければ 0」以降の字は 1 字も変えていない。3 値の意味と「まだ分からない」が「不合格」より先に立つ順序も変えていない。
- **便 142 の契約は「要件書の改訂は要らない」とした。** 契約 §1 (a) の 5 は、根が合わないときの 2 を「判定が実行できないとき」の族（印が読めない・引き金の要約値が測れない）に置き、規範文を変えずに済むとした。一括 22 もこれに従い注だけを直した（一括 22 の仕分け C-3）。36 周目は整合と実態の 2 観点が同じ場所を挙げ、注にだけ在る前提が規範文と逆の答えを読ませることを所見にした。同じ族の「印が読めない」は印の有無の判定の中で起きるので規範文の「印が無い」の近くに読めるが、根の突き合わせは規範文の最初の分かれ道（file の有無）の前に在り、規範文の字だけでは読めない。そこで規範文へ上げる形を推奨にした。

### 判定 2 ＝ 確かめ方と受入基準 AC18 の場合を 7 から 8 にする（歯は変えない）

### 判定 3 ＝ 制約 CON8 の本文を 3 文に絞り、出所と来歴を出所の欄へ移す

- **この場所は 6 周続けて所見が立った。** 27・32・33・34・35・36 周目（§運び方の繰り返しの数え）。中身は毎回別で、34 周目の直し（2 文への割り）が 35 周目のずれ（括弧の出所）を生み、35 周目の直し（括弧 2 つ）の後に 36 周目が 3 文目の「問う句」を拾った。本文が「何を制約するか」と「出所の括弧」と「来歴」の 3 つの役を持ち、どれかを直すと別の役の字が読みにくくなる形である。
- **本文は何を制約するかの 3 文にした。** 1 文目（scribe2 の契約表は移さない）は字を変えていない。2 文目は前の 2 文目と 3 文目を 1 文にまとめた（当てる相手と、導出物を作る口は M3 の口として作ったこと）。3 文目は「設計文書のどこまでを YAML へ移すかを後で持ち主に問うとしていた論点は、移す相手が無くなったので閉じた」にした。ADR-22 の平易文が同じことを「『契約表を持たない設計文書の移行は、M3 の後に改めて問う』の句も、同じ理由で閉じます」と書く中身を、「問う句」と言わずに示した。
- **出所の括弧は文ごとに `source` へ移した。** 一括 22 で直した括弧の中身（2 文目の当てる相手 = ADR-16 決定 (1)(5)・ADR-21 決定 (1)、導出物の口の段 = ADR-16 決定 (5)(7)・要件 FR11・便 119）は字を変えずに移した。1 文目と 3 文目の出所（ADR-22 決定 (1)(2)・ADR-21／ADR-22 決定 (3)）も書いた。ADR-22 決定 (3) の見出しは「(イ) の範囲の論点を閉じる（ADR-3 決定 (8) の (イ) と ADR-16 決定 (1) の末尾の句を狭める）」である。
- **来歴の 3 文は逐語で `source` へ移した。** 「来歴＝第 1.1 版は…取りやめになった（ADR-21）。経緯の詳しい字は ADR-22 の文脈と平易文が持つ。」の字を 1 字も変えず、括弧に「第 1.45 版で本文から出所の括弧と来歴をこの欄へ移した」を足した。前の `source` の字は「ほかの出所＝」の後に全部残した。
- **使った欄は制約の行が既に持つ欄だけである。** 要件書の schema 節は制約の行の欄を列挙しない（要件の行だけ）。床 `crates/folio/src/check.rs` の `check_srs` は制約の行に id と title の非空だけを課す。9 行の制約が実際に持つ欄は id・title・text・basis・source（2 行は rules も）で、要件書の面 `crates/folio/src/face_srs_items.rs` は text と source を「中身」「出所」の列に出す。`note` の欄は制約の行に無く、面にも出ないので使わなかった。新しい欄は足していない。
- **見出しは変えなかった（C）。** 所見の後半は見出しの「段階」を挙げた。見出しは引き金の外で、直しても周は増えない。ただし判断の記録 ADR-3 の注の段（35 周目への応答）が見出しを逐語で引いている（「要件書の制約（契約表を移さないことと導出物を作る口の段階）の本文の同じ句を…」）。見出しを変えると、発効した判断の記録の注が指す字が消える。所見の主な指摘は本文の 3 文目なので、見出しは控えた（問い 2）。

### 判定 4 ＝ 判断の記録 ADR-18 は決定の字を変えず、注に 1 段を足す

- 決定 (5) は発効した判断の記録の決定の欄で、周の引き金の欄である。決定の字を変えるなら判断の記録の作法（改訂の欄 revises を持つ新しい判断の記録）が要る。照らせないときの 2 は、決定 (5) の式が判定を実行できない場合の まだ分からない で、式そのもの（3 値の意味と順序）は変えない。そこで決定の字は 2026-09-24 の発効のままにし、引き金の外の注（`note`）に「【要件 FR20 第 1.45 版との関係】」の 1 段を足した。判断の記録の欄の決まり（`design-intent/adr/schema.yaml`）で `note` は任意の欄で、ADR-18 は既に同じ形の段を 5 つ持つ。
- 段の頭の括弧の承認の字は「持ち主の承認〔承認の後に席が書く〕」にした（承認の後の欄 #5）。
