## 3. 欄への写し方の決まり（種類ごと）

**欄は増やさない。** 書き写す先は、出所の行の種類が既に持つ型付きの欄だけである。欄が受け付ける id の形は、欄の決まり（`adr/schema.yaml`・`srs.yaml` の `schema` 節・`rules.yaml` の `schema` 節）と、**面の生成器が実際に解く形**の両方に従う。後者は歯が守っており、破ると面が「まだ分からない」に落ちる。

| 出所の種類 | 欄 | 受け付ける id の形 | 出所 |
| --- | --- | --- | --- |
| 判断の記録 | `basis` | 条・要件書の 7 節・規則の表の行・判断の記録 | `adr.rs` の `is_basis_id`・`adr/schema.yaml` の `basis_note` |
| 要件・非機能要件 | `basis` | **条の id だけ** | `face_srs.rs` の `article()`（条の題を引く） |
| 要件・非機能要件 | `rules` | 規則の表の行の id | `face_srs.rs` の `rule()` |
| 制約 | `basis` | **条の id だけ** | 同上 |
| 条 | `relations.rules` ほか | 規則の表の行・条・要件書の id | `refs.rs` の `reverse()` |

### 3.1 規範文の id は親の条に落とす

`basis` は「条の id」を持つ欄である。要件書の 77 項はすべて条の id で、判断の記録 12 本の項のうち条を指すものも 1 つの例外なく条の粒である（規範文の id を持つ項は 1 つも無い）。言及が規範文の id（`P-6.4`）のときは親の条（`P-6`）を書く。規範文 ↔ 条 の辺（in-article）が構造として在るので、親の条を書けば規範文へは 1 段で届く。**123 対の「判断の記録 → 規範文」の大半は、親の条が既に `basis` に在ったので何もしていない**（113 件の「既に欄に在る」の主因）。

### 3.2 要件書の `basis` は条の id しか受けない（実装の振る舞い）

起草の途中で、要件書の項の `basis` に判断の記録や他の要件の id を書いたところ、歯 29 本が落ちた。字面は次のとおり。

```
folio build: まだ分からない: srs.yaml.requirements[6].basis[1]: 条 id「FR5」が無い
```

要件書の面の生成器は `basis` の各項を条として解き、解けなければ面ごと「まだ分からない」に落とす。これは**実装の振る舞いであって設計文書の字面ではない**ので、歯を直さず、その対を除外へ回した（§4 の E3b・26 対）。歯は 1 本も直していない（703 件すべて緑）。

### 3.3 欄が空のときは足す

`rules` の欄を持っていなかった要件 2 本（FR6・FR20）には、欄の決まりの任意の欄として `rules` を足した。欄名は新設ではない（`srs.yaml` の `schema.requirement_row.optional` に在る）。
