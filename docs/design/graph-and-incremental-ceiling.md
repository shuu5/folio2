### 1.4 id の形（床が解く範囲）

`scan_ids` が拾うのは、前が英数字でもハイフンでもなく、後ろが英数字でない位置に現れる次の形だけ。

- 条と規範文: `P-` `A-` `N-` に数字、任意で「.数字」の枝番（`P-17.4`）
- 要件書: `FR` `NFR` `AC` `CON` `GOAL` に数字（ゼロ詰めしない）

解決先（母集団）は要件書の 7 つの節の id・条 id・規範文 id・規則行 id と、凍結 anchor の列に在った過去の id。**判断の記録の id（ADR-n）は対象外**で、判断の記録どうしの突き合わせは `crates/folio/src/link.rs` が別に持つ。図の id・設計ノートの文書 id・契約 id（`<doc id>#<行 id>`）も母集団の外。

**節点の id 空間は 3 つに分かれている**（床が解く 3 空間／判断の記録／その他）。索引はこの 3 つを 1 つにまとめる。接頭辞が全部違うので重複は無い。

### 1.7 近傍は何段で足りるか（v1 の中心の主張が落ちた所）

**v1 は「型付きの辺で半径 2 に整合の所見が 100% 収まる」と書いた。これは取り下げる。**

- **最も近い 1 つ**（v1 が使った読み）: その所見を立てるのに「少なくとも 1 つの相手」が半径に入ればよい、とする。

```
5 周に 1 回の全部読みを挟んだ実効（撤退条件 1）
              = (4 × 0.53 + 1.0) ÷ 5 = 62.4% の読む欄  → 538,493 ÷ 2,083,365 = 25.8%
```

**v1 は「26%・いまの 1/4」と書いた。分母が違っていたので数の中身は別物だが、実効値はほぼ同じ約 26% に落ち着く。** 検証役は v1 の数（25.8% と 48.7%）で計算して約 30% と出した。分母を実測へ直すと約 26% になる。

節約は 3 つの掛け算で、寄与はこの順。

| 手 | 効き | 危険 |
| --- | --- | --- |
| ① `reads` の欄まで絞る | 100% → 39.6% | 凍結 anchor の独立性（§8 の G2・追加で手順が要る） |
| ② 節点が変わらない変更は周を回さない | 40 回のうち 14 回が 0 になる | **無しではない（下記）** |
| ③ 影響集合（整合だけ半径 2）で絞る | 39.6% → 21.9% | §1.7 の取りこぼし・§10.2 の 🔴 1 |

**v1 は ② を「危険 無し」と書いた。これは偽である。** 節点にしないと決めた場所（生成区間・欄の決まり・meta）に置かれた所見は 4 観点で **24 件・うち「止める」4 件**（2026-09-20 round4 実態 F-1 = `design-note/schema.yaml` の注が実在しない検査を現在形で宣言・同 round5 実態 F-1・2026-09-21 round22 実態 F-1 = 要件書の生成区間の注・同 round12 整合 F-1 = 天井の正本の schema の注）。そして **14 回の 0 節点 commit の中身は、その場所を触った便そのもの**である（便 76・便 77・部品目録の閉じた一覧・欄の決まりの床の木）。

**したがって ② は「節点が変わらない」ではなく「周の引き金になる場所が変わらない」で判定する**（§3.4）。

## 2. 節点と辺の型

語彙 `design-intent/vocabulary.yaml` に 節点・辺・影響集合 は無い（54 語を実測）。発効するなら語彙に足す。

### 2.1 節点

**節点** = 設計文書の中で id を持ち、1 つのまとまりとして読める単位。欄は 5 つ（id・種類・所属 file・欄の要約値・1 行の題）。

種類は閉じた一覧（条・規範文・規則行・目的・要件・非機能要件・受入基準・制約・判断の記録・設計ノートの節・語・欄の語・天井の観点・天井の節・入口の節・相談の問い・相談の節・要件書の節・憲法の節）。

**この一覧の正本と、辺の型の閉じた一覧の写しを、どの file の生成区間へ導出するか。** v1 は「生成区間へ導出する（FR19 の対象に足す）」と書くだけで file を名指していなかった。名指さなければ便 G1 の契約の行が書けない（受入の章の歯の物差しが定まらない）。

**推奨（🔴 ではない・席の判断）**: 索引は導出物なので、正本の文書の生成区間には置かない。**便 G1 が新しい正本 `design-intent/graph.yaml`（索引の欄の決まり・観点と読む文書の一覧を持つ天井の正本と同じ形）を起こし、その生成区間へ導出する。** この正本は入口の棚（`index.yaml`）と天井の正本の文書の一覧に載るので、その 2 file の版上げが §8.1 に要る。索引の中身そのものは版管理に置かない（毎回組み直す導出物）。

節点の粒は **id を持つ行と、所見の置き場になる節** に取る。file より細かく、欄より粗い。理由は 3 つ。

1. 天井の所見は既に「場所」を `{doc, at}` で書いている。§1.7 の実測で、その場所の 62%（整合）は id で、残りは節の名（語彙の語・天井の観点・要件書の scope）である。**節点の一覧は、所見が置ける場所の一覧と一致していなければならない。**
2. 欄まで細かくすると、辺の端が「どの欄が何の欄に依存するか」になり、いま在る欄（`basis` は条の id を持つだけで、条のどの欄かは言わない）からは導けない。持っていない情報を持っているふりをしない（P-4）。
3. file の粒では §1.6 のとおり中央値で 22% の文書が丸ごと古くなる。

**節点にしないもの**: 生成区間（`schema` 節）・`meta`（承認の来歴・版の来歴）・凍結 anchor・生成物（`preview/`）。ただし §1.8 の実測のとおり、**これらは「周の引き金」には数える**（§3.4）。v1 の §2.1 が書いた「生成区間の変更は床が別に数えており天井の領分ではない」は、この 4 件の止める所見に照らして誤りだった。床が数えるのは生成区間と導出の byte 一致であって、注の中身が実態を偽っていないかは天井の領分である。

### 2.2 辺

**辺** = 節点から節点へ引かれた結び。型は §1.2 の欄から取り、**閉じた一覧**（P-2.4 と同じ扱い）にする。**v1 の 9 型に in-article（規範文 ↔ 条）を足して 10 型。**

| 型 | 向き | 出所 | 伝播に使うか |
| --- | --- | --- | --- |
| basis | 要件・判断 → 条・規則行・要件・判断 | `basis` | 使う（両向き） |
| **in-article** | 規範文 ↔ 条 | 構造（`articles.statements`） | **使う（両向き）** |
| verifies | 受入 ↔ 要件 | `verifies`・`verify.ac` | 使う |
| refs | 要件・設計ノートの行 → id | `rules`・`rows.ref`・`rows.req` | 使う |
| amends | 判断 ↔ 条 | `amends.target`・`amended_by` | 使う |
| relations | 条 → 条・要件・規則行・節 | `relations.*` | 使う |
| goals | 要件 → 目的 | `goals` | 使う |
| article | 規則行 → 条 | `article` | 使う |
| reads | 観点 → 文書 | `viewpoints.reads` | 観点の読む範囲を決めるのに使う（節点間の辺ではない） |
| figures | 要件・判断 → 図 | `figures` | 使わない（図は別の正本） |

伝播は**両向き**に行う。条 P-1 が変われば、それを根拠に挙げる要件 FR1 も読み直しが要り、逆も要る。

#### 散文の言及（mention）

**v1 は「捨てても損は無い」と書いた。これは取り下げる。**

検証役の数え（母集団 1,534）の内訳は、自分の id 176（11.5%）・承認と版の来歴 344（22.4%）・節点に結べない 260（16.9%）・既に辺が在る 332（21.6%）・**本文で指すが型付きの辺が無い 422（27.5%）**。その 422 件の今の段は 2 段 362・**3 段 49・4 段 7・5 段 1**。

本ノートが独立に数え直すと（節点への帰属の取り方が粗いので分類は揃わない）、辺が無い言及 337・うち **3 段以上と届かない 52 件**。**分類の内訳は一致しないが、「本文で指して辺が無い依存が 300〜420 件あり、そのうち 50〜57 件は今の辺では 3 段以上＝半径 2 の外に落ちる」という結論は両者で同じ向きである。**

言及を辺にしない理由は残る 3 つ。

1. 数が多すぎる（型付きの 1.6〜2.5 倍）。承認の来歴と決定の本文に集中しており、その大半は過去の改訂の履歴であって今の依存ではない。履歴を辺にすると古い判断の記録 1 本を直しただけで影響集合が全体へ広がる。
2. 向きが無い。`meta.status_note` の中の `FR19` は、その文書が FR19 に依存しているのか、FR19 を説明しているのか、区別できない。
3. 条 N-2 の向きに反する。**散文にしか無い依存が本当に依存なら、型付きの欄に書き写すべきであって、走査で救い上げるべきではない。**

**その代わり、書き写す便を便の列に入れる**（§8 の G0）。3 段以上に落ちる 50〜57 件を対象に、本物の依存を型付きの欄（`basis`・`rules`・`relations`）へ移す。移せないもの（承認の来歴・説明のための言及）はそのまま残す。

加えて、**参考の列を AI が読んだ結果が所見になったら、その対を型付きの欄へ書き写す**向きを決定に置く。影響集合の出力は、型付きの辺で届かない節点のうち、変わった節点の id を散文に含むものを「参考」の列に別立てで並べる。床はそれを影響集合に数えない。

### 2.3 グラフの正本はどこか

**グラフの正本は設計文書そのもの**（正本 YAML の欄）であり、索引は導出物である（P-6.3）。索引の file を人が書く面は作らない（P-6.4）。索引を持たない状態で影響集合を問われたら「まだ分からない」を返す（P-4.2）。

## 3. 影響集合（何を読み直すか）

### 3.1 定義

**影響集合** = ある変更について、天井の観点が読み直す必要のある節点の集合。観点ごとに違う。

| 観点 | 読む範囲 |
| --- | --- |
| すべての観点（床） | **憲法（27 条・67 規範文）と、その付録（語彙 54 語・規則の表 28 行）と、天井の観点の一覧** を毎周全部 |
| 忠実さ | 床 ＋ 変わった節点 |
| 読みやすさ | 床 ＋ 変わった節点 |
| 整合 | 床 ＋ 変わった節点 ＋（そこから型付きの辺で **2 段** の近傍・両向き） |
| 実態 | 床 ＋ 変わった節点 ＋ その節点に結び付く実装の証拠（契約表の行の要件の列・着地の印の要件 id・歯の名） |

**床に語彙と規則の表を入れる根拠**: §1.7 の実測で、語彙の語（整合 17 件・忠実さ 14・読みやすさ 11）と天井の観点（整合 12 件）に置かれた所見は、その節点が型付きの辺を 1 本も持たないため伝播では永久に届かない。持ち主の指示は「憲法は小さいので毎回見てよい」だったが、語彙と規則の表は入口の棚で憲法の付録（`shelf.annexes` の `inside: constitution`）と定められており、**憲法の一部として毎周読むのは指示の字面の自然な読み**である。費用は 886,260 byte の 31.7%。加えて 4 観点すべてが `reads` に `rules` を持ち、いま既に毎周全部読んでいる。

**整合 以外の 3 観点に半径 0 を与えることは、測って選んだのではない。** §1.7 の表のとおり、3 観点にも床の外の相手を要する所見が 25〜57% ある。4 観点とも半径 2 にすると 1 周は中央値 88% になり増分の意味が消える（§1.8）。**これは費用が選ばせた妥協であり、その対価は §10.1 の撤退条件 1 で数える。**

### 3.2 半径をいくつにするか（🔴 §10.2 の 1）

**推奨は半径 2 のまま**とし、取りこぼしを次の 2 つで受ける。確定は持ち主の判断。

1. **3 段目の節点の id の列を、読ませないが隠さず出力の別の欄に添える。** 観点の AI が必要と判断したら自分で読める（正本は同じ repo にある）。
2. **取りこぼしを撤退条件で数える**（§10.1 の 1）。

半径 3 にすれば 整合 は「指す先の全部」でも 97.7% を捕まえるが、次数の高い節点（P-5 が 35・ADR-8 が 32）を 3 つ通ると辺を持つ節点 218 のほぼ全部に届き、増分でなくなる。

### 3.3 持ち越しは入れない（v1 の §3.3 を落とす・🔴 §10.2 の 2）

**v1 は「前の周で所見が 0 だった観点は判定を持ち越す」と書いた。落とす。**

条 N-3.1（例外機構）に当たるかどうかについては v1 の主張が正しい。持ち越しは旗でも口でもなく、条件は機械で数えられ、1 byte 違えば効かない。**落とす理由は N-3.1 ではない。前提が実測で偽だったからである。**

**実測（過去 25 周・束の要約値で突き合わせ）。同じ要約値の束で 2 度走った観点が 2 つある。**

| 観点 | 周 | 判定 | 所見 | 2 周で共通の所見 |
| --- | --- | --- | --- | --- |
| 忠実さ | round18 / round19 | 合格 / 合格 | 5 件 / 3 件 | **7 種のうち 1 種** |
| 実態 | round18 / round19 | 合格 / 合格 | 2 件 / 3 件 | **4 種のうち 1 種** |

**判定は安定し、所見は安定しない。** 束が 1 byte も違わないのに、round18 だけが挙げた 4 件（P-5 の平易文・語彙の見出し語・FR7 の平易文・ADR-10 の決定）は round19 では出ず、round19 だけが挙げた 2 件（ADR-5 の平易文・NFR1 の平易文）は round18 では出ていない。

v1 の §3.3 は「同じ入力に同じ判定を返しているだけ」と書いたが、**それが成り立つのは判定についてだけで、所見については成り立たない。**

持ち越しを過去 23 周に当てると、**所見の 27.6%（111 / 402）が消える。うち「止める」3 件**（整合 21/109・忠実さ 35/106・読みやすさ 25/78・実態 30/109）。参考までに条件を「その節点が前の周から変わっていない」だけに緩めると 312/402（77.6%・止める 16/26）。**天井の所見の大半は、変わっていない字の上で見つかっている。**（後ろ向きの当てはめなので上限の見積として読むこと。）

さらに **実態 の観点は節点の要約値では守れない**。束の要約値が同じ round18 / round19 で、round19 の 実態 は「便 76 が main f020259 に着地し `crates/folio/src/schema.rs` の TARGETS が 5 本になった」ことを根拠に所見を立てている。**実態 の入力には実装が入っており、それは節点の要約値のどこにも現れない。**

**落としても節約の骨は残る。** §1.8 の効きの表で持ち越しは独立の行を持たず、③ の中に混ざっている。①（読む欄まで絞る）と ②（周を省く）はそのまま残る。

数え直し: `grill/changes.py`・各周の `findings.yaml` の `record.bundle`。

### 3.4 周の引き金（v1 の「危険 無し」を訂正）

節点が 1 つも変わっていない変更でも、次のいずれかが変われば周を回す。

1. 節点の本文の要約値（いずれか 1 つ）
2. **生成区間（`schema` 節）と欄の決まりの file の中身**
3. **面の生成器（`crates/folio/src/face*.rs`・`site.rs`）と部品目録・様式**（面の写しが変わるため）
4. 実態 の観点についてのみ、**実装の証拠（契約表の行・着地の印・歯の名）**

1 だけを引き金にすると、§1.8 の 4 件の「止める」を生んだ場所の変更が天井に 1 度も掛からなくなる。**2 と 3 を足しても、§1.6 の 14 回のうち生成物だけの回（印と部品目録）は残るので、周を省く効きは完全には消えない。** 何回残るかは便 G3 の着地後に実測して台帳へ記帳する（いまは**不明**）。

## 4. 印と門（要件書 FR20 の改訂の範囲）

### 4.1 判断の記録 ADR-8 を狭める改訂である（v1 の帰結の誤りを訂正）

**v1 の帰結は「本判断は判断の記録 ADR-8 の決定を 1 つも捨てない」と書いた。これは偽だった。**

- ADR-8 決定 (4) の逐語: 「天井が合格でない間は、folio2 自身の設計文書の便の着地を既定で止め、再開は所見の解消か持ち主の裁定だけとする」。条件は「天井が合格でないこと」だけで、便が何の file を触るかを問わない。
- 要件書 FR20 の規範文: 「印に不合格の観点が在れば 1（止める）」。同じく便の file を問わない。

v1 の §4.3 は「その観点が不合格を出した節点が、この便の write-set の中の file に在るときだけ止める」とした。これは **ADR-8 決定 (4) の「既定で止める」を「その file を触るときだけ止める」へ狭める**。

**判断の記録どうしの改訂を記帳する型付きの欄が無い。** 判断の記録の欄の決まり（`design-intent/adr/schema.yaml`）の `amends` は条を指す欄で、`amends_entry` の必須欄は `target`・`field`・`version`・`previous_text`・`new_text`。判断の記録を指す `amends`（判断 → 判断）は書けない。散文の注に書くだけでは、条 N-2.1 / N-2.2 が禁じる「散文にしか無い規則」に近づく。

**そこで、欄の決まりに 判断 → 判断 の改訂の欄を足す便（§8 の G7）を列に入れる。** 欄の決まりの生成区間の正本は実装の定数なので、これは `crates/folio/src/adr.rs` の定数の改訂で、便 1 本ぶんである。ADR-13 はその欄で ADR-8 を指す。

### 4.2 緩めるのは「印が古い」の側だけにする（🔴 §10.2 の 3）

**v1 の §4.3 の形のままでは通せない。** 実測が示す穴は 2 つ。

**穴 1: 所見の「場所」と「直す先」は別の file にあることが多い。** 過去の「止める」13 件を手で読むと、**少なくとも 6 件は直す先が場所と別の file にある**（round1 F-1 = 場所 ADR-1 / 直す先 `adr/schema.yaml`・round2 F-1 = 場所 ADR-9 / 直す先 憲法 P-5.1・round3 F-2 = 場所 R-8 / 直す先 R-8 か CON5・round4 F-1 = 場所 ADR-10 / 直す先 天井の正本か ADR-11・round19 F-1 = 場所 FR19 / 直す先 `index.yaml` か要件書・round20 F-1 = 場所 FR19 / 直す先 `ceiling.yaml` か要件書）。場所だけを鍵にすると、**直すべき file の便がすべて素通りする。**

実在した所見で組んだ経路: 2026-09-20 round3 の 整合 F-2（止める・場所は `rules.yaml` の行 R-8・論点は承認を受け取る席の名が R-8 と CON5 と ADR-11 で食い違う）が未解消で 整合 が不合格だとする。便 X が `design-intent/srs.yaml` だけを触り CON5 の本文を書き換える。v1 の門は「不合格を出した節点（R-8）は `rules.yaml` に在る。write-set に `rules.yaml` は無い」と判定して**通す**。便 X は着地し、名は 3 通りに増える。

**穴 2: 周を強制する唯一の仕掛けが外れる。** いまは repo 全体の印が古くなるので、どの便も「まだ分からない」に当たり、周が強制される。v1 の §4.3 はそれを外すので、「誰も触らない file の不合格が、周が起きないまま残る」経路が開く。v1 の撤退条件 5 は単位が「周」なので、**周が起きない失敗の形を数えられない。**

**推奨（確定は持ち主）**:

| 場合 | いま | 推奨 |
| --- | --- | --- |
| write-set に設計文書の正本が 1 つも無い | 通す（0） | 同じ |
| 印が 4 観点とも合格・要約値が今と同じ | 通す（0） | 同じ（節点の要約値が全部一致） |
| 印に**不合格**の観点が在る | 止める（1） | **同じ。repo 全体で止める（緩めない）** |
| 印が無い・古い・「まだ分からない」の観点が在る | まだ分からない（2） | **緩める。古い = 印に無い節点が在る、または要約値が違う節点が在る。その節点がこの便の write-set の file に在るときだけ 2。ほかの file の便は通す** |

**効きはこちらに在る。** §1.6 の 14/40 回（周を省ける回）と、直しの PR の後の「印が必ず古くなる」問題は、どちらも「まだ分からない」の側の話である。不合格を緩めても得られるものは小さく、穴 1 と穴 2 の危険だけが増える。

通したときも、**印の古い節点の数と不合格の節点の数を 1 行で出し、台帳 f2-648 へ記帳する口まで持つ**（出すだけでは撤退条件の材料にならない）。

### 4.3 止まった観点だけ回し直す

節点の単位にすると、直しの PR の後に回し直す観点は「その PR が触った節点を読む観点」だけになる。**ただし観点の数はほとんど減らない。** 床を 4 観点とも毎周読むので、どの節点を触っても 4 観点とも引っかかる場合が多い。減るのは **1 観点あたりに読ませる量**（§1.8）と **周そのものが要らない回**（§1.6・§3.4 の引き金を足した後の実数は不明）である。

## 7. 台帳との絡み

### 7.1 向きと、床に使わないこと

**台帳へは書かない。** 台帳は規則を持たない（P-5.4）。folio が台帳を読むのは **読み取り専用** で、`bd --readonly list --all --json` の出力を受け取るだけにする。

**台帳由来の欄は床の判定に使わない。** 台帳は machine-local で版管理の外にあり（remote の実態は `folio2.git` の `refs/dolt/data`）、そこから導く値は端末と同期の時点で変わる。条 P-3.1 は機械で**決定的に**検査できる項目を床に置くと定め、P-10.1 は検査が凍結 anchor を持つことを求める。**台帳を入力に持つ導出物は、その 2 つと噛み合わない。**

v1 の逃げ（台帳が読めなければ「まだ分からない」）は、**読めるが古い**場合を覆わない。古い台帳は「まだ分からない」ではなく**違う値**を返す。したがって台帳由来の欄は、**面と知らせにだけ使い、床の合否と門の判定には使わない**。門と床が読むのは版管理の中にあるもの（契約表の行・着地の commit の末尾の印）だけにする。

### 7.2 何を繋ぐか

```
要件（FR20）
  └─ 契約表の行（delivery-72.md#bu の req 欄）        ← 87 行・181 件  ［版管理の中・床に使える］
       ├─ 着地の commit（Scribe2-Contract の印）       ← 34 commit     ［版管理の中・床に使える］
       └─ 台帳の行（f2-648.107 の設計への案内）        ← 42 件 → 40 行 ［版管理の外・面と知らせだけ］
```

### 7.3 「要再読」

契約が受け付けられた後にその要件の節点が変わったら、**便の側に「要再読」を出す**。契約の行の `req` が指す要件の節点の要約値を、台帳の行が open になった時点の印の値と比べ、違えば「要再読」。これは便を止める仕掛けではなく、席と器への知らせである（止める判断は門が持つ・増設しない）。

### 7.4 台帳の依存の辺を取り込むか

取り込まない。台帳の行の依存は作業の順序であって、設計文書の関係ではない。読むのは設計への案内 1 種類だけにする。

**節点の単位に置き換える。** 案 B は「× 整合の観点は差分にできないので費用は半分にしかならない」と自分で書いていた。実測でもそのとおりで、整合 は読む欄まで絞っても 59.6% を読む。

### 9.5 近傍を 1 段で切る

**退ける。** 費用は 1 段の中央値 35% に対して 2 段は 53% で、18 ポイント高い。その 18 ポイントで拾えるものを、2 つの数え方で測った。

| 数え方 | 半径 1 が取りこぼす「止める」 | 半径 2 が取りこぼす「止める」 |
| --- | --- | --- |
| 最も近い 1 つ | 1 / 12 | **0 / 12** |
| 指す先の全部 | 10 / 12 | **4 / 12** |

**どちらの数え方でも 2 段が勝つ。** v1 が「2 段なら取りこぼしが 0」と書いた根拠は落ちたが（§1.7）、1 段より 2 段が良いことは両方の数えで一貫している。§10.2 の 🔴 1 で持ち主に問うのは「2 段で足りるか」であって「1 段か 2 段か」ではない。

### 9.6 3 段以上の伝播

**退ける。** 次数の高い節点（P-5 が 35・ADR-8 が 32）を 3 つ通れば辺を持つ節点 218 のほぼ全部に届き、増分でなくなる。代わりに 3 段目の id の列を隠さずに添える。

### 9.7 4 観点とも半径 2 にする

**退ける（費用が許さない）。** 1 周の読む量は中央値 88%・最大 97% になり、増分の意味がほぼ消える（§1.8）。**これは測って選んだ妥協であって、正しさで選んだのではない。** 対価（3 観点の床の外の所見 25〜57%）は §10.1 の撤退条件 1 で数える。

### 9.8 グラフを人が書く file に持つ

**退ける。** P-6.4（2 つの面を人が書き、一致を検査で強制する設計を採らない）。索引は導出物だけにする。

### 9.9 床を「憲法だけ」にする（持ち主の指示の字面どおり）

**退ける。** 語彙の語と天井の観点に置かれた所見（整合だけで 29 件）は型付きの辺を 1 本も持たず、伝播では永久に届かない。語彙と規則の表は入口の棚で憲法の付録と定められている。費用は 12.6% → 31.7%。

## 10. 撤退条件と、持ち主へ上げる問い

### 10.1 撤退条件（P-8.1・数えるのは orchestrator 席・記帳は台帳 f2-648）

1. **影響集合が取りこぼす**: 増分で回した周の後に、影響集合の外に在った節点についての「止める」の所見が、次の全部読みの周で出たら数える。**2 件で本判断を捨て、全部読みへ戻す。** 数えるために、増分の周を **5 周ごとに 1 回** は全部読みの周で挟む。この条件は 整合 の半径 2 と、ほかの 3 観点の半径 0 の**両方**を数える。
2. **（v1 の持ち越しの撤退条件は、持ち越しを落としたので無くなった。）**
3. **索引が費用を取り戻さない**: 索引を組む口（G1）の所要が 1 周の節約分を超えたら数える。**実測 3 回で G6 の絞りを止める**（索引と全体像の出力は残す）。
4. **辺の型が足りない**: 型付きの辺で 3 段以上離れた節点を結び付ける「止める」の所見が **2 件** 出たら、半径を 3 へ上げずに §9.1（根本から作り直す）の設計ノートを起こす。
5. **門を緩めた対価**: 節点の単位の門が「まだ分からない」を出さずに通した便のうち、**着地の時点で印に不合格の節点が残っていた便の本数**を数える。**2 本で §4.2 の緩めを捨て、判定を repo 全体へ戻す。** 単位を「周」ではなく「便の本数」にしたのは、周が起きない失敗の形を数えるためである（v1 の撤退条件 5 はこれを数えられなかった）。
6. **周の引き金が漏れる**: §3.4 の引き金で「周は要らない」と出した後に、次の周でその変更に由来する「止める」の所見が出たら数える。**2 件で引き金の判定をやめ、設計文書の file が 1 つでも変われば周を回す形に戻す。**
7. **数えられない回**が規則の表の行 R-7 の回数を超えたら、本判断の撤退条件の判定を「まだ分からない」に落として持ち主へ渡す（条 P-4.2・P-11.1）。

### 10.2 持ち主へ上げる 🔴 5 点

**1. 半径 2 の実証が落ちた。どう進めるか。**
過去 23 周の整合の所見を「所見が要る指す先を全部」で測り直すと、2 段以内は 64.8%、「止める」12 件のうち 4 件が 3〜4 段でした。v1 が「2 段で 100%」と書いた根拠は、指す先のうち最も近い 1 つだけを見た数えです。
選べる道は 3 つ。(a) 半径を 3 にする（増分の節約はほぼ消えます）。(b) 半径 2 のまま、取りこぼしを「3 段目の id の列を添える」で受け、撤退条件 1 で数える。(c) 辺の型が足りないと見て §9.1（根本から作り直す）へ戻る。
**推奨は (b)。** ただし (b) を採るなら、**持ち主の第 2 の選択肢はまだ退けられていない**ことを受け入れることになります。

**2. 持ち越しを入れるか。**
天井は AI の判定で、束が 1 byte も違わない 2 周を突き合わせたところ、判定（合格）は一致しましたが、挙がった所見 7 種のうち両方で挙がったのは 1 種だけでした。過去 23 周に持ち越しの条件を当てると、所見の 27.6%（「止める」3 件を含む）が消えます。
**推奨は「持ち越しは入れない」。** 入れなくても節約の骨（読む欄まで絞る・周を省く・影響集合で絞る）は残ります。

**3. 門を緩めるか。緩めるならどこまでか。**
v1 は「不合格の節点が在る file を触る便だけ止める」でしたが、所見の直す先は場所と別の file にあることが多く（「止める」13 件中 6 件）、直すべき file の便が素通りします。さらに、いまは「印が古い」が全部の便に当たるので周が必ず回りますが、v1 の形はその仕掛けを外すので「誰も触らない file の不合格が、周が起きないまま残る」経路が開きます。
**推奨は、緩めるのを「まだ分からない（印が古い）」の側だけにし、「不合格」は repo 全体で止めるを残すこと。** 効き（周の 14/40 回が要らなくなる）はそちらに在り、危険はこちらに在ります。

**4. 判断の記録 ADR-8 の決定 (4) を狭めることを、どう記帳するか。**
ADR-13 は ADR-8 決定 (4)（天井が合格でない間は着地を既定で止める）を狭めますが、判断の記録どうしの改訂を記す型付きの欄がありません。条 N-2 は散文にしか無い規則を規則として扱いません。
**推奨は、判断の記録の欄の決まりに 判断 → 判断 の改訂の欄を足し、ADR-13 にその行を置くこと**（便 G7a・1 本増）。

**5. 要件書の面から「未実装」が消える。代わりを置くか。**
いま要件書の面には「未実装」が 7 か所出ており、持ち主は面を開けば動くかどうかを読めます。v1 はこれを注から落としますが、便の列には導出物を面へ出す便がありませんでした。
**推奨は、面へ出す便を列に入れること**（便 G8）。面を組む file（`face_srs.rs`）の余地は 115 行で M の便が入らないため、**先に file を割る便（G7b）が要ります**。3 値は機能要件だけに当て、非機能要件（NFR1・NFR2）は対象外として注を手書きのまま残します。

### 10.3 まだ確かめていないこと

- §1.3 の散文の言及の件数は、走査の範囲を実装の定数で閉じるまで（便 G1）動く。**いまの値は幅でしか言えない。**
- §3.4 の周の引き金を足した後に、周を省ける回が 14/40 から何回に減るかは**不明**。便 G4 の着地後に実測して台帳へ記帳する。
- §1.7 の数えは、所見が言葉だけで指した関係（整合で 4 件・ほかの 3 観点で 32〜42 件）を数えていない。**グラフでは扱えない所見がこれだけある**ことは測れたが、その所見が増分で失われるかどうかは測れていない。
- 検証役の散文の言及の数（1,534）と本ノートの数（1,187〜1,805）が一致しない理由は**不明**。同じ script を本ノートの作業場所で走らせると 1,188 が出る。
